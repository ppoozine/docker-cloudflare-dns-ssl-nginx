## What this project is

A four-container Docker stack for serving multiple domains over HTTPS with
Let's Encrypt wildcard certs (Cloudflare DNS-01). Designed as a learning
scaffold and as a usable scaffold for small personal/internal deployments.

If a request implies "production-grade SaaS" or "I want zero ops," push back
toward Caddy or Traefik — this scaffold trades simplicity of moving parts
for visibility into how nginx + certbot actually work.

## Architecture (one paragraph)

`nginx` (1.27-alpine) terminates TLS and reverse-proxies to apps on the host
via `host.docker.internal`. `certbot` (dns-cloudflare:v2.11.0) runs
`certbot renew` every 12h; on success its post-hook touches
`certbot/signal/reload`. `certbot-watcher` polls that path every 30s and,
when present, calls `docker exec nginx nginx -s reload` through
`docker-proxy` (`tecnativa/docker-socket-proxy:0.3.0`), which whitelists
exactly the daemon endpoints `exec` needs. The flag file is removed **only on
successful reload** so a transient reload failure retries on the next cycle.

## Multi-domain config layout

- `nginx/snippets/` — shared `include`-able fragments (ssl, headers, gzip, proxy, acme)
- `nginx/vhosts/00-http-globals.conf` — http-scope helpers (`$connection_upgrade` map)
- `nginx/vhosts/_example.conf.example` — skeleton, NOT loaded by nginx (extension)
- `nginx/vhosts/<domain>.conf` — one file per domain, generated by `add-domain.sh`

Adding a new domain is `./add-domain.sh <domain> [--upstream-port N]`. Removing
a domain is `rm nginx/vhosts/<domain>.conf` + `docker compose up -d --force-recreate nginx`.

## Critical "do not regress" list

Mistakes that real users hit in this codebase; do not reintroduce.

- **Use `certbot/dns-cloudflare`, not `certbot/certbot`.** The latter has no
  cloudflare plugin, wildcard renewal silently fails.
- **DNS-01 only.** Wildcard certs cannot be issued over HTTP-01 / webroot.
- **`cloudflare.ini` must live in `certbot/secrets/`, not `certbot/conf/`.**
  `certbot/conf` is mounted read-only into nginx; an attacker who compromises
  nginx would otherwise read the Cloudflare API token.
- **Renewal `certbot renew` must pass `--dns-cloudflare-propagation-seconds 30`.**
  The plugin default (10s) is unreliable against Cloudflare's global propagation.
- **Watcher must NOT delete the reload signal on a failed reload.** Use
  `if docker exec ... reload; then rm -f /signal/reload; fi` so the next poll
  retries.
- **One reload trigger only.** Use `certbot/conf/renewal-hooks/post/reload-nginx.sh`,
  not a `--post-hook` flag in compose. Two paths doing the same thing confuses
  maintainers.
- **No reload loop inside the nginx container.** The watcher owns reloads.
- **No OCSP stapling directives.** Let's Encrypt stopped including OCSP
  responder URLs in leaf certs in 2024. `ssl_stapling on` produces a warning
  and does nothing. `ssl_trusted_certificate` and `resolver` are only there
  to support OCSP and should also stay out.
- **Healthcheck targets `/health`, not `/`.** `/` is proxied to the upstream,
  so `/` healthcheck conflates nginx liveness with upstream liveness. The
  internal `location = /health { return 200; }` is the right probe.
- **Healthcheck uses HTTPS.** The HTTP port redirects to HTTPS, which would
  cause wget to follow the redirect and fail SNI on `localhost`.
- **Upstreams bind to `0.0.0.0`, not `127.0.0.1`.** The host loopback is not
  reachable from inside the nginx container. Use the firewall / security
  group to keep the port off the public internet.
- **`/etc/nginx/conf.d/` inside the container is ephemeral.** It's a bind
  mount of `nginx/vhosts/` (currently read-only). Don't try to
  `docker exec nginx vi /etc/nginx/conf.d/...`. Edit the file on the host
  and run `docker compose up -d --force-recreate nginx` (or `restart nginx`).
- **Never reintroduce the deleted helpers.** `auto-renew.sh`,
  `nginx-log-cleanup.sh`, `nginx-to-cloudwatch.sh`, and `default.conf.template`
  were all replaced by something simpler or correct.

## Conventions

- Secrets only via `.env`. Parse it with regex, **never** `source` (avoids
  shell injection on edge-case values).
- Pin image versions. No `:latest`.
- Bash: `set -euo pipefail` and quote variables.
- Before adding any new helper script, ask whether nginx or Docker already
  solves this. They usually do.
- Project docs (README.md, CLAUDE.md, .claude/rules/*.md) are written in
  English. Conversation with the user can be in 繁體中文.

## Modification checklist

Run through this before committing:

- [ ] No secrets hardcoded in committed files
- [ ] Image tags pinned, no `:latest`
- [ ] None of the deleted helpers reintroduced
- [ ] No reload loop added to nginx
- [ ] `cloudflare.ini` still in `certbot/secrets/`
- [ ] `certbot renew` still passes `--dns-cloudflare-propagation-seconds 30`
- [ ] Watcher's `rm` is still conditional on reload success
- [ ] Exactly one reload-trigger path
- [ ] Modified `nginx/vhosts/*.conf`? Plan to recreate nginx after deploy
- [ ] Modified `nginx/snippets/*.conf`? All vhosts that include it get
      the change automatically — verify none break
- [ ] Modified `_example.conf.example`? Existing vhosts are NOT regenerated;
      either accept the drift or run `add-domain.sh --force-vhost` for each
