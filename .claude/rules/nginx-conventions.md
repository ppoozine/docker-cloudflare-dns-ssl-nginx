# Nginx conventions

## File layout

```
nginx/
├── snippets/                     mounted to /etc/nginx/snippets:ro
│   ├── ssl-common.conf           TLS protocols, ciphers, session
│   ├── security-headers.conf     HSTS, X-Frame-Options, etc.
│   ├── gzip.conf                 compression for text-like types
│   ├── proxy-headers.conf        X-Forwarded-*, WS upgrade, timeouts
│   └── acme-challenge.conf       .well-known/acme-challenge location
└── vhosts/                       mounted to /etc/nginx/conf.d:ro
    ├── 00-http-globals.conf      $connection_upgrade map (http scope)
    ├── _example.conf.example     skeleton; not loaded (extension)
    └── <domain>.conf             one per domain, generated by add-domain.sh
```

`nginx/vhosts/` corresponds 1:1 to `/etc/nginx/conf.d/` in the container. Any
`*.conf` file there is loaded; any other extension is ignored.

## Adding a vhost — preferred path

```bash
./add-domain.sh <domain> [flags]
$EDITOR nginx/vhosts/<domain>.conf
docker compose up -d --force-recreate nginx
```

The script issues the cert (if needed) and scaffolds the vhost file from
`_example.conf.example`, substituting `__DOMAIN__`, `__UPSTREAM_HOST__`,
`__UPSTREAM_PORT__`, and `__UPSTREAM_PATH__`.

### Upstream flag matrix

| Flag | Default | Use for |
|------|---------|---------|
| `--upstream-host HOST` | `host.docker.internal` | Different host (another container, internal IP, internal DNS). For a container, the service must be reachable on a network nginx is attached to. |
| `--upstream-port PORT` | `3000` | Service port. |
| `--upstream-path PATH` | empty | Append to upstream URL. Must start with `/`. Almost always wants a trailing `/` too (`/api/`) so nginx strips the location prefix when forwarding. |

Composed examples:

```bash
# Default: proxy / to http://host.docker.internal:3000
./add-domain.sh foo.com

# Different port
./add-domain.sh foo.com --upstream-port 8080

# Different host (another container in the same compose network)
./add-domain.sh foo.com --upstream-host api-svc --upstream-port 8080

# Sub-path on upstream (request /users → upstream /v1/users)
./add-domain.sh foo.com --upstream-port 3000 --upstream-path /v1/

# Internal IP, different VLAN, sub-path
./add-domain.sh foo.com --upstream-host 10.0.0.5 --upstream-port 8080 --upstream-path /api/
```

For multi-location vhosts (mix proxy + static, route different paths to
different backends, rate-limit a path), generate the scaffold first and then
hand-edit using the cookbook examples included in the generated file.

## Adding a vhost — manual path

If you need shape beyond the skeleton:

```bash
cp nginx/vhosts/_example.conf.example nginx/vhosts/<domain>.conf
$EDITOR nginx/vhosts/<domain>.conf            # replace __DOMAIN__ and __UPSTREAM_PORT__
docker compose up -d --force-recreate nginx
```

The cert still needs to be issued separately — call `./add-domain.sh <domain>`
first (it'll skip the vhost generation step if you've already written one).

## Snippet rules

- A snippet is a fragment, not a full nginx config — it should be safe to
  `include` from any matching scope (http vs server vs location).
- `proxy-headers.conf` is **location-scope only**. Including it at server
  scope works but causes confusion when something doesn't apply.
- `acme-challenge.conf` is **server-scope** (it defines a `location` block).
- Adding a new shared bit (e.g. CSP header tuning, custom log format)?
  Add a new snippet — don't extend an existing one with unrelated
  directives.

## Where the `map` directive lives

The `$connection_upgrade` map must be at http scope. `conf.d/*.conf` files
are included inside the `http {}` block, so `vhosts/00-http-globals.conf`
is at the right level. The `00-` prefix ensures it loads before any vhost
that depends on `$connection_upgrade`.

If you need additional http-scope helpers in the future (e.g. another `map`,
a `limit_req_zone`, an `upstream` block), they go in
`vhosts/00-http-globals.conf` or in a similarly-prefixed file
(`vhosts/01-rate-limits.conf` etc.).

## Reverse proxying to host services

```nginx
location / {
    proxy_pass http://host.docker.internal:<port>;
    include /etc/nginx/snippets/proxy-headers.conf;
}
```

`host.docker.internal` works because compose injects an `extra_hosts` entry
mapping it to `host-gateway`. The upstream service must bind to `0.0.0.0`
(or the docker bridge IP); `127.0.0.1` on the host is invisible from the
container.

## Reverse proxying to other containers

If the upstream is another container on the same compose project, prefer
the docker DNS name:

```nginx
location / {
    proxy_pass http://other-service:8080;
    include /etc/nginx/snippets/proxy-headers.conf;
}
```

Add the service to the compose file with `networks:` so nginx can reach it.
Update `.claude/rules/architecture.md` if the topology changes meaningfully.

## Health endpoint

Every vhost generated from the skeleton has:

```nginx
location = /health {
    access_log off;
    return 200 "ok\n";
}
```

This is what the docker healthcheck probes. Don't remove it without
updating the compose healthcheck — otherwise the container will be
flagged unhealthy.

## SSL settings

- `ssl_certificate` / `ssl_certificate_key` are per-vhost (cert is per-domain).
- Everything else (protocols, ciphers, session) lives in
  `snippets/ssl-common.conf` — keep them centralized.
- Do not add `ssl_stapling on` to any vhost. See the "do not regress" list
  in `CLAUDE.md`.

## Cert paths

Always `/etc/letsencrypt/live/<domain>/{fullchain,privkey}.pem`. The
`certbot/conf/` mount in nginx is `:ro`, so nginx will surface a clear
error if you reference a cert that hasn't been issued.

## When NOT to add a snippet

If a directive only makes sense for one vhost (custom upstream config,
domain-specific rewrites, a header that only one app needs), put it inline
in that vhost. Snippets are for things shared across multiple vhosts.

## Multi-location patterns (cookbook)

The generated vhost includes commented examples. Quick reference:

### Route a sub-path to a different backend

```nginx
location /api/ {
    proxy_pass http://api-backend:8080/;          # trailing / strips the /api/ prefix
    include /etc/nginx/snippets/proxy-headers.conf;
}
```

Request `/api/users` → upstream sees `GET /users`. Drop the trailing `/`
to forward the prefix too (upstream sees `GET /api/users`).

### Mix static + proxy

```nginx
location /assets/ {
    root /usr/share/nginx/html;
    expires 7d;
}

location / {
    proxy_pass http://host.docker.internal:3000;
    include /etc/nginx/snippets/proxy-headers.conf;
}
```

More specific locations win; `/assets/foo.png` reads from disk, everything
else proxies.

### Block a path entirely

```nginx
location ~ ^/(admin|internal)/ {
    return 403;
}
```

### IP allowlist on a path

```nginx
location /private/ {
    allow 10.0.0.0/8;
    deny all;
    proxy_pass http://host.docker.internal:3000/private/;
    include /etc/nginx/snippets/proxy-headers.conf;
}
```

If the request comes through a Cloudflare proxy, `$remote_addr` is
Cloudflare's edge IP. Use the `real_ip` module with Cloudflare's published
ranges if you need accurate client IPs for ACLs.

### Rate-limit a path

Define the zone once in `vhosts/00-http-globals.conf`:

```nginx
limit_req_zone $binary_remote_addr zone=login:10m rate=5r/m;
```

Then per-vhost:

```nginx
location /login {
    limit_req zone=login burst=10 nodelay;
    proxy_pass http://host.docker.internal:3000;
    include /etc/nginx/snippets/proxy-headers.conf;
}
```

`limit_req_zone` is http-scope (hence `00-http-globals.conf`); `limit_req`
is location-scope.

## When to stop using add-domain.sh

When the same domain needs structural changes beyond what flags express
(multiple locations with different backends, custom rewrites, domain-only
quirks), just hand-edit `nginx/vhosts/<domain>.conf` directly. Re-running
`add-domain.sh` would refuse to overwrite anyway, and the per-vhost design
is explicitly intended to absorb arbitrary nginx config without the script
needing to understand it.
